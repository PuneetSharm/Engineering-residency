### Answer

I want to become an engineer instead of someone who simply knows a programming language because I often feel that I have gaps in understanding what needs to be done in a project and which approach would be the most appropriate.

# Part 2 – Mental Models Reflection

## 1. What is the difference between memorising a concept and building a mental model?

### Answer

Memorising a concept means remembering its definition, syntax, or a few important points without fully understanding the reasoning behind it.

Building a mental model means understanding the complete picture by answering questions such as:

- What problem does it solve?
- Why does that problem exist?
- Why was this solution created?
- How does it work internally?
- What are its limitations?
- What trade-offs does it introduce?
- When should I use it?
- When should I avoid it?

Instead of remembering isolated facts, a mental model helps me connect different ideas and understand how they work together.

## 2. Choose one technology you currently use.

### Technology

React.js

---

### What problem does it solve?

React helps developers build user interfaces using a component-based architecture, making applications easier to develop, maintain, and scale.

---

### Why do you think it was created?

Based on my current understanding, React was created to simplify the development of complex user interfaces.

It introduced reusable components, JSX, and a more efficient rendering mechanism using the Virtual DOM. These features help developers build large applications more efficiently while improving maintainability and performance.

I believe there is still more to learn about the original problem React was designed to solve, and I expect to understand that in greater depth later in this residency.

---

### What existed before it?

Before React, developers primarily used JavaScript to manipulate the DOM directly.

HTML, CSS, and JavaScript were often separated into different files, and updating the user interface required manually selecting DOM elements and modifying them.

As applications became larger, this approach became more difficult to maintain.

---

### What do you still not understand about it?

Although I can build applications using React, I believe there are many concepts I still need to understand more deeply.

For example:

- Why React's rendering system works the way it does.
- How reconciliation actually works internally.
- How React makes rendering decisions.
- Why certain design decisions were made.
- How React behaves internally beyond the APIs that I use every day.

---

## 3. Which technology do you think you have mostly memorised rather than understood?

### Answer

I generally remember concepts by recognising patterns.

When I encounter a similar situation again, I can usually understand and apply the solution more effectively.

However, looking back honestly, I believe there are several technologies that I have used more through pattern recognition than through a deep understanding of their underlying principles. React itself is one example where I know how to use many features but still want to understand the reasoning behind them more thoroughly.

---

## 4. Biggest Insight

### Answer

One of my biggest insights is that strong mental models are built through practical experience, experimentation, and understanding real-world problems.

Simply knowing how to use a technology is not enough.

To become a better engineer, I need to understand why it exists, what problems it solves, what limitations it has, and how experienced engineers decide when to use it.
