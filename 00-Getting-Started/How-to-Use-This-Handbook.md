# How to Use This Handbook

> **"Learning a technology makes you productive. Learning engineering makes you adaptable."**

---

# Welcome

Welcome to the **Engineering Residency**.

This handbook is designed to take you from being a **React Developer** to becoming an **AI Product Engineer** who understands not only how to write code, but why software is built the way it is.

This is **not** a tutorial.

This is **not** a crash course.

This is **not** an interview question bank.

Instead, it is a structured engineering curriculum that combines theory, implementation, real-world practice, engineering judgement, and long-term thinking.

By the end of this residency, the goal is not just to know React or AI tools. The goal is to think and work like an engineer.

---

# What Makes This Handbook Different?

Most learning resources teach technologies one by one.

For example:

- Learn HTML
- Learn CSS
- Learn JavaScript
- Learn React

While this approach teaches syntax, it often leaves important questions unanswered:

- Why was this technology created?
- What problem does it solve?
- What alternatives exist?
- What trade-offs does it introduce?
- How is it used in real production systems?

This handbook answers those questions before teaching implementation.

Understanding always comes before memorization.

---

# The Goal of This Residency

The purpose of this residency is to help you become an engineer who can:

- Understand problems before writing code.
- Read and understand unfamiliar codebases.
- Learn new technologies independently.
- Make informed engineering decisions.
- Build scalable and maintainable applications.
- Explain technical concepts clearly.
- Debug issues methodically.
- Design complete software solutions instead of isolated features.

Technology changes over time.

Engineering principles remain valuable.

# How to Study Each Chapter

Follow the same process every time.

## Step 1 — Read

Read the chapter slowly.

Do not skim.

Try to understand every paragraph before moving forward.

---

## Step 2 — Think

Ask yourself questions.

Examples:

- Why does this exist?
- What problem does it solve?
- Would software still work without it?
- What are its limitations?

Thinking is part of studying.

---

## Step 3 — Read Official Documentation

Whenever the handbook recommends official documentation, read only the specified sections.

Documentation is an important engineering skill.

Learning to navigate documentation is just as valuable as learning syntax.

---

## Step 4 — Experiment

Modify code.

Break things intentionally.

Observe what changes.

Real understanding comes from experimentation.

---

## Step 5 — Build

Implement what you learned.

Small implementations reinforce theory.

Larger implementations gradually become part of Developer OS and your Portfolio.

---

## Step 6 — Reflect

Complete the journal.

Write what you learned.

Write what confused you.

Write what you want to revisit.

Reflection strengthens long-term memory.

---

## Step 7 — Review

Before beginning the next chapter, briefly review the previous one.

Small, regular reviews are more effective than occasional long revision sessions.

# Progress Through the Residency

This handbook is designed to be followed sequentially.

Do not skip chapters.

Many later topics depend on earlier foundations.

If a chapter is unclear, pause and resolve your doubts before continuing.

Strong foundations reduce confusion later.

Treat this repository like a real engineering project.

Commit your progress regularly.

```bash

git commit -m "docs: complete day 0 part 1"

```

Your Git history will become a record of your engineering journey.

# A Note About AI

AI is an incredibly powerful tool.

Throughout this residency, AI will act as:

- Mentor
- Reviewer
- Pair Programmer
- Interviewer
- Teacher

However, AI should never replace your own thinking.

Always attempt to understand a problem before asking AI for a solution.

The objective is to improve your engineering ability, not simply produce code faster.

# What Success Looks Like

By the end of this residency, success is not measured by the number of technologies you know.

Instead, ask yourself:

- Can I understand unfamiliar systems?
- Can I explain why a technology exists?
- Can I evaluate engineering trade-offs?
- Can I build software confidently?
- Can I debug complex issues?
- Can I learn new technologies without waiting for tutorials?

If the answer to these questions is "yes", then this residency has achieved its purpose.
